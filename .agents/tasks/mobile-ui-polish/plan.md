Design decisions (made here, grounded in the code):

- **Overlay approach**: position the opened mobile `.nav-menu` as `position: fixed` anchored just below the sticky navbar (`top: var(--topbar-height)`), full-width, with its own `--color-surface` background, a bottom border + shadow for elevation, and `z-index: 1100` (above navbar's 1000). Fixed (not absolute) avoids dependence on the wrapping navbar's computed height and guarantees it floats over content without shifting it. Rationale: the content under the navbar must not move; fixed positioning removes the menu from normal flow entirely.
- **Backdrop/scrim**: add a single reusable `#nav-backdrop` element in index.html (dimmed, `z-index: 1050`, below the menu, above content) toggled with the `.open` state. Clicking it closes the menu. Rationale: gives an obvious tap-to-dismiss affordance on mobile and visually separates the overlay from busy dashboard content.
- **Animated background scope**: replace the landing-only `#landing::before` with a shared, page-level animated background rendered via a `body::before` (gradient wash) and `body::after` (soft drifting blobs) so it applies to ALL index.html sections AND bulletin.html with zero markup changes. `pointer-events: none`, `position: fixed`, `z-index: -1`, behind `.navbar`/`main` content. Rationale: CSS-only, no JS loop, applies everywhere automatically, GPU-friendly (animates only `transform`/`background-position`/`opacity`). Keep contrast: cards/panels already use opaque `--color-surface`; the wash uses very low-alpha brand tints (same alpha range as the current `#landing::before`, ≤ .08).
- **No FEAT decomposition**: the three concerns are tightly coupled CSS/markup/JS changes over the same four files with shared stacking context and breakpoints; they do not form independently shippable features. A single ordered plan is the right granularity.

Manual verification is required for all items (no automated test suite exists; this is presentation-layer work). Serve via XAMPP and use browser DevTools device toolbar. Standard verification matrix referenced below as **[MATRIX]**:
