# Implementation Plan

## Grounded decisions

- Keep the application dependency-free and frontend-only: `index.html` and `bulletin.html` are the only linked user-facing pages, both load `style.css`, and the inspected PHP endpoints already provide every required contract. Do not change `api/**`, `create_admin.php`, or `test_mail.php` unless a frontend regression proves an essential compatibility fix is needed.
- Use the existing top navigation for public/auth views and turn the existing admin tab strip into the Nock-inspired ~240px workspace rail on wide screens; keep the resident dashboard as a compact service workspace rather than inventing analytics. This adapts the reference hierarchy to actual barangay services while minimizing selector and behavior risk.
- `style - Copy.css` has no references anywhere in the project; leave it untouched. Centralize all live styling in `style.css` rather than maintaining two conflicting copies.
- Preserve the current no-framework architecture and use Plus Jakarta Sans through an optional Google Fonts `<link>` with the fallback stack `"Plus Jakarta Sans", "Segoe UI", system-ui, -apple-system, BlinkMacSystemFont, sans-serif`; the interface must remain fully usable when that request or Font Awesome fails.
- The repository has no `.git` directory, README, `AGENTS.md`, `CONTRIBUTING`, `.kiro/steering`, dependency manifest, or test runner. Use the verified local runtimes (`node`, `C:\xampp\php\php.exe`, live XAMPP at `http://localhost/barangay_portal_new/`, and Chrome) and record manual/browser evidence as specified below.
